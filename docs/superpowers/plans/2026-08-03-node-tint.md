# Node Tint and Palette Yellow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the left accent bar on a coloured service node with the same tinted treatment a coloured note gets, and add a yellow to the colour palette.

**Architecture:** The node's modifier class is renamed `node--accented` → `node--tinted`, the `::before` bar is deleted, and every fixed colour on the card derives from `--node-color` via `color-mix` — the same mechanism and ratios the note already uses. The existing contrast test is generalised from notes to both entity kinds and gains the node's secondary-text tier.

**Tech Stack:** React 18, TypeScript, Vite, vitest, `@testing-library/react` + jsdom, CSS `color-mix`.

## Global Constraints

- Prettier `{ "singleQuote": true, "semi": false, "printWidth": 100 }`. Run `npx prettier --write <files>` before every commit; `npm run format:check` is a CI gate.
- All npm/vitest commands run from `webapp/`. Git commands from the repo root.
- Component tests need `// @vitest-environment jsdom` as the file's FIRST line. `src/entityContrast.test.ts` is a PURE node-environment test and must NOT have one. No global vitest `environment` setting, no vitest config file.
- `npm run typecheck`, `npx vitest run` and `npx vite build` must all be clean before any commit. The suite currently has **389** passing tests.
- **An entity with no colour must render byte-identically to today.** Every derived rule stays scoped under `.note--tinted` / `.node--tinted`. Do NOT convert them to unconditional rules with `var(--x, fallback)` defaults — it looks equivalent and silently changes default rendering.
- The contrast threshold is **4.5:1** (WCAG AA). If a colour fails, change the derivation ratio — never the threshold.
- `.node__status` (the up/down/idle dot), icon images, and `.node.selected` are deliberately NOT derived.

- [ ] **Step 2: Write the failing tests**

Add a `NODE_SECONDARY_TEXT_MIX_PERCENT` constant beside the existing ones:

```ts
// .node--tinted .node__sub and .node__field-k
const NODE_SECONDARY_TEXT_MIX_PERCENT = 45
// .node--tinted .node__icon--placeholder background
const NODE_PLACEHOLDER_MIX_PERCENT = 25
```

Then append inside the top-level `describe`:

```ts
  it.each(PALETTE)('reaches AA for %s on node primary text over the card tint', (hex) => {
    const base = hexToRgb(hex)
    const background = colorMix(base, BACKGROUND_MIX_PERCENT, WHITE)
    const text = colorMix(base, TEXT_MIX_PERCENT, BLACK)
    expect(contrastRatio(background, text)).toBeGreaterThanOrEqual(MIN_CONTRAST)
  })

  it.each(PALETTE)('reaches AA for %s on node secondary text over the card tint', (hex) => {
    const base = hexToRgb(hex)
    const background = colorMix(base, BACKGROUND_MIX_PERCENT, WHITE)
    const text = colorMix(base, NODE_SECONDARY_TEXT_MIX_PERCENT, BLACK)
    expect(contrastRatio(background, text)).toBeGreaterThanOrEqual(MIN_CONTRAST)
  })

  it.each(PALETTE)('reaches AA for %s on the icon placeholder', (hex) => {
    const base = hexToRgb(hex)
    const background = colorMix(base, BACKGROUND_MIX_PERCENT, WHITE)
    const placeholder = colorMix(base, NODE_PLACEHOLDER_MIX_PERCENT, background)
    const text = colorMix(base, TEXT_MIX_PERCENT, BLACK)
    expect(contrastRatio(placeholder, text)).toBeGreaterThanOrEqual(MIN_CONTRAST)
  })
```

Note the placeholder background composites over the card tint, exactly as the code/pre case does — `color-mix(… 25%, white)` in the CSS paints over the already-tinted card, so the test mixes against `background`, not `WHITE`.

## Notes for the implementer

- **The compatibility promise is load-bearing.** "Absent colour renders exactly as today" is why every derived rule lives under a modifier class. Do not refactor them into unconditional rules with `var(--x, default)` fallbacks — that changes default rendering subtly and silently, and two existing tests exist to catch it.
- **Colour is one-way by design.** There is no reset; a coloured entity cannot return to its default. That was decided deliberately. Do not add a reset affordance back as a "fix".
- **`.node__status` stays its own colour.** If a reviewer or your own instinct says it looks inconsistent, that is the intended trade: status is information, not decoration.
- **Do not touch** `webapp/server/`, `src/diff.ts`, `src/model.ts`, or the Inspector. This change is rendering plus one palette entry.
