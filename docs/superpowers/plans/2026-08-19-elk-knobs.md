# ELK Layout Knobs in Diagram Settings Implementation Plan (Feature A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose ELK's layout options as per-diagram knobs in the Diagram Settings dialog (Waypoint router), applied on Tidy, so ELK output can be tuned and compared.

**Architecture:** An `ElkConfig` on `Diagram.routing.elk` (persisted via the existing `diagram.setRouting` op) drives a pure `elkLayoutOptions()` helper that `layoutHierarchical` uses instead of hardcoded ELK options. Dialog `ElkControls` edit it; an "Apply & Tidy" button commits then re-runs layout.

**Tech Stack:** React 18 + TypeScript + Vite + vitest; elkjs.

export function elkLayoutOptions(elk: ElkConfig): Record<string, string> {

## Notes for the implementer

- `DEFAULT_ELK` deliberately sets `nodePlacement`/`crossingMin` to ELK's own layered defaults (`BRANDES_KOEPF`/`LAYER_SWEEP`), which the current code leaves unset — so emitting them explicitly does not change default output.
- ELK is server-side: these knobs do nothing until **Tidy** runs. The Apply & Tidy button is the intended loop; `await sendOps(...)` before `onTidy()` guarantees the layout reads the just-committed config.
- Only topology diagrams route through `layoutHierarchical`; that's the intended scope for now.
