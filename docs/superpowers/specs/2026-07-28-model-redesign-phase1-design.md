# Model redesign — Phase 1: entity-base model, no catalog, uuids

**Status:** Approved (design), pending implementation plan.
**Date:** 2026-07-28
**Branch:** `feat/model-redesign` (off `main`).
**Supersedes:** `2026-07-28-opaque-edge-ids-design.md` (the edge-only migration; this replaces it).

Phase 2 (MCP resolution layer — search-by-name, disambiguation, richer returns) is a **separate
spec**. This phase makes the new model work end-to-end with MCP tools minimally adapted to uuids.

## Goal

Replace the current catalog-based model with a flat, diagram-local model where every object is an
`Entity` (base type = a uuid identity) with `Node` / `Group` / `Note` / `Edge` subtypes. No shared
catalog, no placement indirection, uuid ids throughout. Existing diagram data is **disposable** —
no migration; start fresh.

## Motivation

The `Entity`/`Placement` split and the `model.entities[]` catalog exist only to support one logical
entity appearing across multiple diagrams (shared identity). The ad-hoc-entities pivot already made
that ~1:1, so the machinery is now accidental complexity. Groups and notes are *already* modeled the
target way (diagram-local, inline position). This makes nodes consistent with them and deletes a
large amount of plumbing. It also fixes the original trigger — edge ids embedding `from-to` and going
stale on reconnect — by moving every id to an opaque uuid.

## The model

```
Entity (base)         { id: string }              // uuid, pure identity

Node   extends Entity  { label; icon?; sub?; status?; actor?; template?; fields: Field[];
                         position: XY; parentId?: string }        // diagram.nodes[]
Group  extends Entity  { label; color; position: XY; size; parentId?: string }  // diagram.groups[]
Note   extends Entity  { text; position: XY; size; parentId?: string }          // diagram.notes[]
Edge   extends Entity  { from; to; type; label?; points?; sourceHandle?; targetHandle?;
                         dir?; color?; labelPos?; orientation?; shape? }         // diagram.edges[]

Diagram { id; name; title; type; nodes: Node[]; groups: Group[]; notes: Note[];
          edges: Edge[]; flows: Flow[] }
Flow / FlowStep       unchanged (steps reference element uuids via elementIds)
Template              unchanged (model.templates[], referenced by Node.template)
Model  { version; diagrams: Diagram[]; templates: Template[] }   // NO entities[]
```

- **`Node`** = today's `Entity` merged with `Placement`: it owns its `position`, `parentId`, and its
  own `fields` directly.
- **Ids:** bare uuid v4 everywhere, generated by a shared helper (`newId()` in `webapp/src/ids.ts`,
  using the `uuid` lib — `getRandomValues`-based, so it works on the plain-HTTP LAN; **not**
  `crypto.randomUUID()`). Every object type uses it: nodes, groups, notes, edges, diagrams, flows,
  steps, templates.
- **Containment:** `parentId` (child→parent, single source of truth) on `Node` / `Group` / `Note`.
  The container is always a `Group`. Nested groups and grouped notes are supported. `Edge` has no
  `parentId`.

## What is deleted (the payoff)

- `model.entities[]`, `entitiesById`, and the catalog write-back / placement reconciliation.
- `Placement` as a type (merged into `Node`), and `Placement.fieldShow` (per-diagram field-visibility
  override) — a node owns its fields' `showOnNode` directly, nothing shared to override.
- `Placement.note` → just a field on `Node`.
- `EntitiesPage.tsx` (deleted). `Palette.tsx` is already unused (shelved) — delete it too.
- Ops `entity.*` and `placement.*` collapse into `node.*` (see below).

## Subsystem changes

- **`webapp/src/model.ts`** — new types + base; mutators become `node.*` (add/update/remove/setFields/
  applyTemplate) replacing `entity.*`+`placement.*`; `addNode` places directly in a diagram;
  `removeGroup` generalizes to free `Node`/`Group`/`Note` children; templates mutators unchanged;
  `normalizeModel` targets the new shape and, on encountering an **old-shape model** (top-level
  `entities`), returns a fresh empty model (disposable data — no migration).
- **`webapp/src/ids.ts`** (new) — `newId()` → uuid v4.
- **`webapp/src/ops.ts`** — replace `entity.*`/`placement.*` op variants with `node.*`; drop
  `placement.fieldShow`; `edge.*`/`group.*`/`note.*`/`flow.*`/`template.*`/`diagram.*` keep their
  shapes (retyped: `DEdge`→`Edge`, etc.).
- **`webapp/src/diff.ts`** — diff `diagram.nodes[]` (by uuid) instead of `entities[]`+`placements[]`;
  emit `node.*` ops.
- **`webapp/server/store.ts` / `history.ts`** — `DiagramContent` gains `nodes[]`, drops the
  entity/placement split; history/undo works on the new content shape (unchanged mechanism).
- **`webapp/src/buildGraph.ts`** — build React Flow nodes from `nodes[]`/`groups[]`/`notes[]` and
  edges from `edges[]`; **emit parents before children topologically** so nested groups render;
  keep `edge.id = de.id` behavior. Groups/notes get `parentId` handling.
- **`webapp/src/App.tsx`** — write-back (`*ToDiagramParts`) maps canvas → `nodes/groups/notes/edges`;
  create handlers mint uuids via `newId()`; **cycle guard on reparent** (a group can't become its own
  ancestor); remove all catalog/entitiesById logic.
- **`webapp/src/Inspector.tsx` / `nodes.tsx` / `WaypointEdge.tsx`** — read fields off `Node` directly
  (no placement/fieldShow indirection).
- **`webapp/server/mcp.ts`** — tools operate on the new model (nodes, uuids). Terminology moves
  `entity`→`node` where user-facing in tool names/args; creation/authoring tools **return the uuid(s)**
  they create; tools that take an id take a uuid. `get_diagram` returns the full model (uuids +
  labels) so an agent can find a uuid by label until Phase 2's search lands. (The full resolution
  layer is Phase 2.)
- **Delete** `webapp/src/EntitiesPage.tsx`, `webapp/src/Palette.tsx`, and their references/CSS.

## Naming

`Entity` is the base term for any model object. The current `Entity` (service/actor canvas object)
is renamed **`Node`**. `Placement` disappears. MCP `entity`-named tools/args become `node`.

## Data reset

Existing `model.json` / `history.json` (git-ignored runtime state) are discarded. `normalizeModel`
detects the old shape and seeds a fresh empty model; equivalently, clearing the runtime files seeds
fresh. No migration code ships.

## Out of scope (Phase 2+)

- MCP resolution layer: `find`/search by name/description → uuid(s) with disambiguating context;
  richer create returns; tool-description overhaul.
- Nested-group UX polish beyond correct rendering/containment.
- Any re-introduction of a shared catalog/library (explicitly deferred; add later only with firm
  requirements).

## Testing

- **Unit** (`model.test.ts`, `ops.test.ts`, `diff.test.ts`, `history`/`store` tests): new-model
  mutators (`addNode`/`updateNode`/`removeNode`, containment free-on-group-delete for all child
  kinds, cycle guard); `node.*` ops round-trip through diff; `normalizeModel` resets an old-shape
  model to empty; `newId()` uniqueness.
- **Browser (Playwright)**: create nodes/groups/notes/edges; nest a group inside a group and a note
  inside a group and confirm containment/drag; flows still light elements; reconnect still works;
  reload persists. (Interactive checks may need the user when the browser is locked.)
